# v1.0.3 性能与体感优化（实测记录）

> 环境：Intel HD 4000 / ANGLE(D3D11) / 800×500 视口 + 2× 整数缩放 / Godot 4.7.2
> 采样：自动加载脚本每秒写 `logs/performance.log`（FPS、帧时、尖峰、对象数、drawcall）

## 一、实测数据

| 场景 | FPS | 平均帧时 | 最大帧时 | drawcall | 对象数 |
|---|---|---|---|---|---|
| 启动 + 首页动画 | 46.7 | 21.4 ms | **142.9 ms** | 106 | 3364 |
| 首页稳态 | 60.0 | 16.7 ms | 16.7 ms | 106 | 3364 |
| 进入游戏 / 页面重建 | 31.7 | 31.5 ms | **134.3 ms** | 109 | 3528 |
| 游戏中稳态 | 60.0 | 16.7 ms | 16.7 ms | 147 | 3543 |
| 个别页面切换 | 48-57 | 17-21 ms | 40-83 ms | 124-157 | 3606 |

**结论：稳态是满帧 60fps；"卡"发生在【场景/页面切换】与【存档】这两类瞬间（100ms+ 尖峰）。**

## 二、根因

1. **存档体积过大（主因）**
   - 你的档：第 **778 天 / 41 家公司 / 275 名员工 / 40 只股票**
   - 未压缩世界 JSON = **141 MB**；每槽实际占用 ≈ **162 MB**（2 份 active + 1125 个 solid 历史分片）
   - 4 个槽合计 **648 MB**
   - 每次保存 = 141MB 序列化 + Brotli 压缩 + 写入 + 1100+ 分片校验 → 秒级 CPU/IO → 主线程尖峰
2. **页面切换同步重建 UI**：游戏用代码即时构建界面，切页/开面板时会有 130-150ms 的单帧卡顿（原设计）
3. **高刷屏帧率错配**：`Engine.MaxFps` 被硬编码为 60；若显示器是 120/144Hz 且开垂直同步，会出现节奏性顿挫
4. **诊断脚本自身开销（已修）**：上一版每 0.5 秒递归 stat 4500 个分片文件

## 三、v1.0.3 已实施

| # | 优化 | 说明 |
|---|---|---|
| 1 | **解除 60fps 硬上限** | `Engine.MaxFps` 60 → 0，交给垂直同步/显示器刷新率决定（144Hz 屏不再顿挫） |
| 2 | **诊断扫描收窄** | 只监视 `saves/*.json`（4 个槽位文件），不再递归 4500 个分片；频率仍 0.5s |
| 3 | **性能采样转正** | `logs/performance.log` 每秒一行；`查看游戏日志.bat` 会带上最后 15 行 |
| 4 | **快捷操作（F1/F5/F9/F11/F3）** | 纯 GDScript 注入，复用游戏已有按钮：F5 快速保存到手动槽1、F9 快速读档、F11 全屏、F3 性能浮层、F1 帮助；输入框聚焦时自动让行 |
| 5 | **存档磁盘体检** | `存档自检.bat` 现在会列出每槽占用（active/solid 明细）+ 合计，并标注孤儿目录 |
| 6 | **安全清理** | 新增 `存档修复.bat` 同目录的 `clean`：只删**孤儿 .parts** 与残留 `*.tmp`，不动被引用的分片 |

## 四、还能进一步优化（有取舍，需你确认）

| 方案 | 收益 | 代价 | 做法 |
|---|---|---|---|
| **A. 缩短滑动存档窗口**（120 天 → 30 天） | 每槽 162MB → 约 40MB，存档/读档明显变快 | 可回滚的历史天数变短 | 改 `SlidingSaveWindow.Days` 默认常量（IL 一行） |
| **B. 降低自动存档频率** | 减少周期性尖峰 | 需要改 C# 逻辑（IL 注入较复杂），断电回退进度略多 | 待评估 |
| C. 精简世界规模 | 根因解除 | 影响玩法 | 玩家侧选择 |
| D. 杀软排除 | 减少写入延迟抖动 | 需要管理员权限 | 把 `%APPDATA%\Godot\app_userdata\泡沫年代 - Bubble Years` 加入排除 |

## 五、怎么自己定位卡顿

1. 进游戏按 **F3** 打开性能浮层（FPS / 帧时 / 对象数 / drawcall）
2. 觉得卡时看数字：
   - FPS 掉但 drawcall/对象没暴涨 → 多半是**存档**在跑（看 `logs/save-activity.log` 同时刻是否有写入）
   - drawcall 暴涨到 200+ → 界面元素过多（切页/大列表）
3. 事后用 `查看游戏日志.bat` 看 `performance.log` 的对应分钟
