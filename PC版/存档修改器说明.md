# 存档修改器（SaveEditor）使用说明

> 工具：`存档修改器.bat` → `工具\SaveEditor\SaveEditor.exe`
> **务必先完全退出游戏再改**，改完后进游戏读取对应槽位生效。

## 一、能改什么

| 分类 | 字段 |
|---|---|
| 基本信息 | 天数、公司现金、个人现金、公司债务、个人债务、公司名称 |
| 员工（全部 276+ 人，含主角） | 姓名、六项能力（智力/魅力/口才/美术/音乐/技术）、满意度、月薪、岗位 |

改能力时会**同步**写入 `Abilities[]` 与对应的 `Design/Engineering` 字段，避免出现"显示了但计算用的是旧值"。

## 二、操作流程

1. 双击 `存档修改器.bat`
2. 先看列表确认槽位（`manual-1` / `auto-1` …）
3. 输入槽位（如 `manual-1`）回车
4. 主菜单：
   - `1` 基本信息 → 按编号改，改完 `0` 返回
   - `2` 员工 → 输入员工编号 → 改姓名/能力/满意度/月薪/岗位 → `0` 返回
   - `3` **保存并退出**（会重建分片，141MB 世界约需数秒）
   - `0` 放弃
5. 进游戏 → 「读取存档」→ 选该槽位

## 三、安全性

- 保存前会自动把该槽位的 `*.json / *.json.bak` 复制到 `saves\.editor-backup-<时间>\`
- 保存走游戏自己的 `SaveRepository.Write`（与游戏内保存同一条路径），会做世界校验；
  校验不通过会**直接报错且不写盘**，原存档保持不变
- 改数值建议保持合理范围（如现金不要给到 10^18 以上、能力 0–999、满意度 0–100）

## 四、关于"锁满意度"

游戏原本会让满意度每天向"目标值"缓慢漂移（系数 0.12），所以改完会慢慢回落。
v1.0.3 已在程序集里把该**漂移系数改为 0**（`BeginCareerDay` 里的 `* 0.12` → `* 0.0`），
因此：

- 编辑器里设成多少，游戏里就**一直是那个值**
- 员工不会再因为工资低/欠薪而掉满意度（欠薪时的 0 覆盖逻辑仍在，避免"欠钱还满满意度"）

> 想恢复原版漂移？把 `game\assemblies\original\BubbleYears.Simulation.dll` 覆盖回 `assemblies\patched\`
> 并重新 `dotnet build`（同时会丢掉"联网运营"存档修复，不建议）。

## 五、常见问题

| 现象 | 原因/处理 |
|---|---|
| 提示"槽位不存在或不可读" | 输错了槽位名；或该槽位是空槽 |
| 保存失败：`扩展存档：xxx` | 世界校验拒绝（把某项改成了非法值）。按提示改回合理值重试 |
| 保存很慢 | 正常：世界 JSON 141MB，需要序列化+压缩+重建分片 |
| 改完进游戏没变化 | 需要在游戏里**读取该槽位**（不是"继续游戏"读了别的档） |
| 想还原 | `saves\.editor-backup-<时间>\` 里的 json 复制回槽位；或用 `存档修复.bat` |
